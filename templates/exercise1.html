演習1：ログイン画面でSQLインジェクション攻撃を体験しよう
難易度：★☆☆（初級） 対象：ログイン機能
1. 演習の目的
この演習では、ログインフォームに対するSQLインジェクション攻撃を体験し、 「脆弱な書き方」と「正しい対策」のイメージをつかむことを目的とします。
2. 想定される脆弱な実装
query = "SELECT * FROM users WHERE username = '" + username + "' AND password = '" + password + "'"
cursor.execute(query)
3. やってみよう
右側のログインフォームを使って、次のように試してみてください：
  • ① 普通にユーザ名／パスワードを入力してみる
  • ② パスワードに ' だけを入れる
  • ③ 「ヒント」を見て、SQLが真になる文字列を考えて入力してみる
ヒントを見る（クリックで展開）
＋

・パスワード欄に、常に条件が真になる論理式 を足してみましょう。

例：

  • ユーザ名：admin
  • パスワード：' OR '1'='1 --
SELECT * FROM users
WHERE username = 'admin'
AND password = '' OR '1'='1' -- '

'1'='1' が真であるため、認証をバイパスできます。

4. 学習のポイント
  • 文字列連結でSQLを作る危険性を体験する
  • Prepared Statement が防御になる理由を理解する
  • エラーの挙動から内部構造が推測されてしまう怖さを知る
5. SQLインジェクションを防ぐための方法（対策）
ログイン機能のようにユーザー入力を扱う箇所では、「入力値をSQL文字列に連結しない」ことが基本です。 特に次の対策を組み合わせることで、SQLiの多くを防止できます。
  • プレースホルダ（Prepared Statement / パラメータ化クエリ）を使用し、SQL構造と値を分離する
  • 入力値の検証（バリデーション）：想定される形式・長さ・文字種を満たさない入力は拒否する
  • エラーメッセージの抑制：DBの詳細なエラーを画面に出さず、ログにのみ記録する
  • 最小権限の原則：アプリ用DBユーザーには必要最小限の権限のみ付与する
  • パスワードは平文で照合しない：ハッシュ化して照合する（漏洩時の被害を抑える）
6. 安全な実装例（パラメータ化）
            -- 悪い例（文字列連結：SQL構造が壊れる）
            SELECT * FROM users
            WHERE username = '${username}' AND password = '${password}';

            -- 良い例（プレースホルダ：値はSQLとして解釈されない）
            SELECT * FROM users
            WHERE username = ? AND password_hash = ?;

            # Python例（DB-APIのプレースホルダを利用）
            cursor.execute(
            "SELECT * FROM users WHERE username = ? AND password_hash = ?",
            (username, password_hash)
            )
7. 演習のまとめ
この演習で体験した認証バイパスは、「入力値がSQLの一部として解釈される」ことで成立します。 対策の要点は、SQL文字列の連結をやめてパラメータ化すること、そして入力検証・エラー抑制・最小権限を合わせて実装することです。
