演習6：脆弱なコードを静的解析で見つけてみよう
難易度：★★★（上級） 対象：Python / Flask コード
1. 演習の目的
これまでの演習では、実際にフォームやURLから攻撃を行いました。 この演習では視点を変え、「ソースコードを読んで脆弱箇所を見つける」 静的解析を体験します。

実際の開発現場では、コードレビューや静的解析ツールが SQLインジェクション対策の重要な役割を担っています。
2. 対象となる脆弱なコード
例として、次のような Flask アプリの一部を考えます： 
@app.route("/search")
def search():
    q = request.args.get("q", "")
    query = "SELECT * FROM items WHERE name LIKE '%" + q + "%'"
    cursor.execute(query)
    rows = cursor.fetchall()
    return render_template("search.html", rows=rows, q=q)
このコードのどこが問題か、自分の目で確認してみましょう。
3. やってみよう
右側の「脆弱コード」欄を読み、以下の観点から危険な行を探してみてください：
  • ユーザ入力（request.args / request.form）はどこか
  • その値はどのようにSQL文へ渡されているか
  • 文字列連結は行われていないか
  • パラメータバインド（プレースホルダ）は使われているか
ヒントを見る（クリックで展開）
＋

● SQLインジェクション観点で見るべきポイント

  • ・request.args.get / request.form.get から取得した値
  • ・"... " + 変数 + " ..." のような文字列連結
  • ・cursor.execute(...) に直接埋め込まれているか
  • ・WHERE や LIKE の条件にユーザ入力を入れていないか

これらがそろっている場合、静的解析ツールは「SQLインジェクションの疑いあり」と判定できます。

4. 学習のポイント
  • ・静的解析では「データの流れ（データフロー）」を見る
  • ・入力元（ソース）→ SQL実行箇所（シンク）を追跡する
  • ・プレースホルダを使えば、静的解析でも「安全な書き方」と判断しやすい
  • ・自動ツールと人間のレビューを組み合わせることが重要
