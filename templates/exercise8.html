演習8：安全なSQL（防御版）を体験しよう
難易度：★☆☆（初級〜中級） 対象：Prepared Statement / パラメータバインド
1. 演習の目的
これまでの演習では、脆弱なSQLに対して攻撃を行ってきました。 この演習では、「正しい書き方」を用いると攻撃がどう防げるのか を体験します。

具体的には：
  • 文字列連結による危険なSQL
  • プレースホルダ（%s や ? など）を使った安全なSQL
  • 同じ入力でも結果がまったく変わること
を比較し、パラメトリクエリがなぜ強力なのかを理解します。
2. 脆弱な書き方 vs 安全な書き方
例えばログイン処理は、次のように書くと危険です： 
# ❌ 脆弱な例（文字列連結）
query = (
    "SELECT * FROM users WHERE username = '" + username +
    "' AND password = '" + password + "'"
)
cursor.execute(query)
一方、次のようにプレースホルダ＋パラメータを使うと安全になります： 
# ✅ 安全な例（パラメトリクエリ）
query = "SELECT * FROM users WHERE username = %s AND password = %s"
cursor.execute(query, (username, password))
プレースホルダを使うと、username や password の中身は 「SQLの一部」ではなく「単なる値」として扱われるため、 ' OR '1'='1 などが入ってもSQLとして解釈されません。

● 防御のポイント

  • SQL文と値を絶対に文字列連結しない
  • DBドライバが提供するプレースホルダを必ず使う
  • 入力値は型チェック（長さ・形式）も行う
  • ORM（SQLAlchemyなど）も内部でパラメトリクエリを使っている

この演習では、同じ攻撃ペイロードでも安全な実装なら防げることを体感してください。

3. 学習のポイント
  • 防御は「入力を変える」のではなく「SQLの書き方を変える」
  • パラメトリクエリはSQLインジェクション対策の“第一候補”
  • 静的解析・動的解析の両方で「安全」と判断されやすい書き方
  • 現場のコードレビューでも必ずチェックされるポイント
