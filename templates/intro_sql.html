SQLインジェクションとは？
Webアプリで最も危険な脆弱性のひとつ
1. どんな攻撃？
SQLインジェクション（SQL Injection）とは、 Webアプリケーションの入力欄に SQL文の一部を挿入 して 本来意図しないクエリを実行させる攻撃です。

主な被害：
  • 認証回避（パスワードなしログイン）
  • 情報漏えい（ユーザー情報の抽出）
  • データ改ざん・削除
  • 内部構造の暴露（テーブル一覧の取得など）
2. なぜ発生するのか？
原因のほとんどは ユーザ入力をSQLに直接結合している ことです。 
SELECT * FROM users WHERE username='入力値';
こうしたコードは、攻撃者の入力がそのままSQLとして実行されてしまいます。
3. 攻撃例：不正ログイン
攻撃者が次のように入力：
' OR '1'='1 
SELECT * FROM users
 WHERE username='' OR '1'='1'
 AND password='';
1=1 は常に真 → ログイン突破
4. どう防ぐ？（概要）
SQLインジェクション対策の基本は次の4つ：
  • ✔ パラメトリクエリ（プリペアドステートメント）
  • ✔ 入力値の検証・エスケープ
  • ✔ エラーメッセージを漏えいさせない
  • ✔ ORM（SQLAlchemy）の利用
このアプリ全体では、 脆弱→攻撃→静的解析→動的解析→安全版 の流れを体験できます。
SQLインジェクションのしくみ（図解）
ユーザー入力 → SQL文へ直接連結 → DBが実行 → 結果漏えい

この流れのどこか1つでも問題があると攻撃が成立します。
脆弱コード例（まとめ）
username = request.form.get("username")
query = "SELECT * FROM users WHERE username='" + username + "'"
cursor.execute(query)
安全な書き方（例）
cursor.execute(
    "SELECT * FROM users WHERE username = %s",
    (username,)
)
パラメトリクエリを使うと、 DBドライバが自動でエスケープ処理を行うため SQLインジェクションは根本的に無効化されます。
